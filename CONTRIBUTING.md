# Contributing to MotorsportVerse

Thanks for helping build the open-source motorsport AI ecosystem.

## Ways to contribute

1. **Add a sport** — the highest-leverage contribution. See
   [docs/adding-a-sport.md](docs/adding-a-sport.md).
2. **Improve the shared packages** — `motorsport-core` / `motorsport-data`.
3. **Improve the ecosystem website** — catalog UX, project pages.
4. **Register a concept** — add a `registry/projects/<slug>.json` entry for a
   sport you'd like to see.

## Development setup

```bash
pip install -e "packages/motorsport-core[dev]" "packages/motorsport-data[dev]"
cd website && npm install
```

## Before opening a PR

```bash
# Python
ruff check packages projects scripts
pytest packages/motorsport-core packages/motorsport-data projects/f2-predictions

# Registry (if you touched registry/projects/*)
python scripts/build_registry.py

# Published data (if you touched ANY export)
python scripts/validate_published_data.py

# Shared components or their tests (if you touched components/{ui,magicui}/
# or __tests__/shared/ on any site)
node scripts/sync_shared_ui.mjs --check

# Any website you touched
npm test && PAGES_BASE_PATH= npm run build
```

CI runs exactly these. PRs must be green.

Optionally, install the hooks so the same gates run before the commit rather
than after: `pip install pre-commit && pre-commit install`.

## The three rules that are enforced, not suggested

These have their own gates because each one has been broken here before, and
each broke silently.

1. **Baselines and evidence.** Any change touching a model or a probability
   states its metric against a *named baseline* over *named rounds*. See
   [docs/EVIDENCE.md](docs/EVIDENCE.md). A comparison that loses is published as
   a loss — the `EvidencePanel` has no code path that hides one.
2. **A fix that belongs to every series goes in `packages/`.** The flagship once
   fixed a calibration incoherence in its own tree; five cloned series published
   broken probabilities for a month because the fix never reached the shared
   package. If you are fixing something in `projects/<one series>/` that is not
   about that series' data source or its format, you are probably fixing it in
   the wrong place. See [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md).
3. **Never fabricate data.** Sparse coverage stays genuinely missing. This
   includes scaffolds: the five in-development series return an empty calendar
   rather than a plausible one, and there are tests asserting it.

## Conventions

- **Python**: 3.11+, `ruff` (E/F/W), line length 100. Keep `motorsport-core`
  dependency-light (no sport constants, no web/plotting in the import path).
- **Leakage discipline**: any multi-round aggregation must filter to rounds
  strictly before the target round and assert it with
  `motorsport_core.leakage.assert_prior_only`.
- **Schema changes**: update `motorsport_data.schema` and the TS mirror in
  `website/src/types/registry.ts` together; prefer additive changes.
- **The registry is the source of truth** for the catalog. Don't hand-edit
  `registry/index.json` or `website/public/data/registry.json` — they're
  generated by `scripts/build_registry.py`.
- **F1 is the reference.** When a design question has no obvious answer, match
  what the flagship `projects/f1-predictions` does — and then ask whether the
  answer belongs in `packages/` so every series gets it.
- **Design**: [DESIGN.md](DESIGN.md) is the reference. The hub and the series
  sites are deliberately different surfaces; most mistakes are one's rule
  applied to the other. Shared components style through CSS custom properties
  and never hardcode a colour — one source has to render under six accents.
- **Chart colour is validated, not chosen.** Use the `--viz-*` tokens. If you
  need a new one, run the dataviz validator against all three chart surfaces
  with `--pairs all` and record the numbers, as DESIGN.md §1.4 does.

## Adding a shared-core module

If you extract more reusable logic from a project into `motorsport-core`, add it
to `__init__.__all__`, give it a test under `packages/motorsport-core/tests/`,
and document it in [docs/core-api.md](docs/core-api.md).

## Adding a shared component

The canonical copy lives in
`projects/f1-predictions/website/src/components/{ui,magicui}/`. Edit it there,
then run `node scripts/sync_shared_ui.mjs` to push it to every site — editing a
target directly is how drift happens, and CI will catch it.

A deliberate per-site divergence goes in `TARGET_EXEMPTIONS` **with its reason
written above it**. Do not use the global `SITE_SPECIFIC` set for that: it drops
the file from the gate on *every* site, so the next real drift goes unnoticed.
